# MeowID 接入与部署

## 配置

API Key 等配置保存在 EMAS 现有 `app_secret` 记录中，不写入小程序。

| 字段 | 用途 |
| --- | --- |
| `MEOWID_PROJECT_ID` | MeowID 项目编号 |
| `MEOWID_API_KEY` | 项目密钥，需识别、猫咪读写及任务读取权限 |
| `MEOWID_BASE_URL` | HTTPS 接口根地址，默认 `https://platform.meowid.net` |
| `MEOWID_TOP_K` | 识别候选数量，默认 5 |
| `MEOWID_ENROLL_IMAGES_PER_CAT` | 仅“按上限同步”使用的每猫累计上传上限，至少 5 的整数，默认 5 |

服务参数在「识猫服务 → 服务配置」保存；每猫图片上限在「识猫服务 → 数据同步」填写并点击“保存同步上限”，独立保存。私有 COS 图片仍使用已有 COS 配置；密钥只写不回显。旧精选筛选、广告和每日额度设置不用于 MeowID 模式。

## 部署

更新完整 `functionsEMAS/unionOp/`（含 `meowid.js`、`meowidSync.js`、`meowidTiming.js`、原模块与生产依赖），执行时限至少 60 秒，然后重新编译小程序。原独立 `catFace` 保留，不修改 `timeTrigger`，不增加云函数或定时器。

在 `unionOp` 目录安装生产依赖后打包，ZIP 根目录应为 `index.js`、各模块、`package.json` 和 `node_modules`。不要把 ZIP 放入待打包目录。

模式存于 `setting/pages.recognize.mode`：`off` 关闭，`custom` 原服务，`meowid` 新服务。关闭模式会停止新的识别和审核上传；正在执行的批次可能尚未结束。

## 图片上限与续传

- 「全量 / 增量同步」默认同步全部猫咪档案及审核通过的照片，不要求精选，不限制每猫数量，也不要求先保存上限。之前因上限暂缓的 `limited` 照片可直接补传。
- 「按上限同步」使用单独保存的每猫累计名额。上限填 10，已有 8 张受理记录时只补 2 张；审核照片不足 5 张时按实际数量上传。达到上限的照片保留为 `limited`，提高并保存上限后可继续补传；调低上限不删除远端图片。
- 上限模式中，已受理、处理中、处理失败但有回执、以及结果待核对的上传都计入名额；不存在回执的明确拒绝不占用名额。
- 新增照片审核通过后自动上传，不受手动同步上限限制。手动批次之间共享项目租约；单张审核使用照片级原子占用，不会被历史同步或状态刷新占用的项目锁拦住。同一张照片正在处理时返回“同步处理中”，已有回执和待核对记录仍不会重复提交。
- 页面打开时连续请求后续批次，离开页面后停止发起新批次。重新点击同一种方式可继续；切换方式后重新扫描档案并按所选规则补传，保留原上传回执。
- `syncAll` / `syncNext` 的 `syncMode` 参数默认为 `all`；只有明确传入 `limited` 才应用上限，每批均需携带该参数。刷新状态不改变批次方式。

## 状态与防重复

同步记录保存在 `cat.meowid_sync`、`photo.meowid_sync` 和按项目隔离的进度文档中，保留旧远端编号及登记记录。有任务编号或图片编号的照片不再次上传，即使其状态异常为 `retry`。

上传结果不明时保留 `uncertain`，不自动重传；旧 `cat.meowid_images` 的不完整历史也需先核对。新上传保存内容 SHA256 和唯一文件名，刷新任务时可按文件名与远端猫咪编号找回原任务。旧通用文件名 `photo` 无法可靠自动配对，需人工核对，不能清空同步记录重传。

页面显示本地已关联的猫咪数和剩余猫咪数，以及有受理记录的已上传图片数和剩余图片数，每组相加等于总数。剩余图片包括上限暂缓、失败及结果待核对的记录，不全都可以自动补传；猫咪数也不代表平台项目的总猫咪数。

“已上传（已受理）”不等于“注册完成”。开始、每五批及结束时分批刷新原任务，`queued/running` 表示平台仍在处理。多猫图片的 `waiting_user` 需要在 MeowID 控制台确认目标猫咪。

平台显示“已放弃”的任务对应 `cancelled`，会同步为已放弃状态并保留原任务回执，不会自动重新上传。

下载失败等明确未提交的操作可退避后补传；平台拒绝的格式/大小错误不会无限重传。本地照片记录去重不等于不同记录的全局图片内容去重，也不能自动识别没有本地关联的手工上传。

同步不删除已有线上图片，不自动清理照片转移后的旧远端向量。接口格式、限流与第三方用量以 [MeowID 开发者文档](https://meowid.net/developers) 为准。

## 请求超时

- 识别、建档、图片上传的单次 HTTP 等待上限：50 秒。
- 猫咪与任务状态查询：40 秒；原图下载：15 秒。
- 整批执行预算：55 秒；每次 HTTP 请求还受剩余预算限制，并为返回结果保留时间。下载后至少保留约 30 秒的上传预算，剩余时间不足时由下一批继续。
- 小程序等待 MeowID 云函数及审核上传：60 秒。EMAS 客户端请求上限为 60 秒，不能通过 SDK 参数无限延长；需要更久的操作必须改为异步任务。
- 防重复租约延长为 70 秒，覆盖较长请求。上传超时仍保留待核对状态，不自动重传。

时间参数集中在 `meowidTiming.js`。检查连接与刷新任务状态分开调用，避免在同一个 55 秒批次内叠加两个慢查询。部署时必须同步更新完整 unionOp 和小程序，云函数执行超时设为至少 60 秒。

平台限制：[EMAS 系统限制](https://help.aliyun.com/zh/document_detail/606199.html)。
