# 用户成就系统

用户通过浏览、关注、拍照、写便利贴、点赞等互动点亮成就徽章。徽章有 3D 立体效果、刻有获得者昵称和编号，可在个人主页展示，并参与成就榜排名。

本系统与按猫等级发放的「猫猫徽章」（`badge_def`）相互独立。

## 一、徽章素材：Enamel Cat Badges

正面图由开源 skill **Enamel Cat Badges（珐琅猫咪徽章）** 生成：<https://github.com/xuannfx/enamel-cat-badges>。支持单枚、平行多款、分级系列，以及节气、节日等主题。流程为先写策划单（猫、主题锚点、接触动作、构图），再展开提示词出图。

要求：真实 Alpha 透明 PNG（非白底、非棋盘格画进 RGB），建议 512×512。

该仓库目前未附 LICENSE，对外分发参考素材前需向作者确认授权。

## 三、规则

每枚徽章有一条规则，达成即发放：

```js
rule: {
  metric: 'photo',                               // 统计项
  count: 1,                                      // 门槛，1～100000 的整数
  window: { start: '2026-02-03', end: '2026-02-05' }, // 可选：时间限定
  agg: 'days',                                   // 可选：days 按不同天数 / cats 按不同猫数，缺省按次数
  filter: { catId: '...' },                      // 可选：指定猫猫
}
```

### 统计项

| 统计项 | 成就页类别 | 统计口径 | 时间依据 | 时间限定 | 天数 / 猫数 | 指定猫猫 |
|---|---|---|---|---|---|---|
| `view` | 猫口普查 | 看过的不同猫数 | 无 | ✗ | ✗ | ✓ |
| `follow` | 吸猫 | 关注的猫数 | 无 | ✗ | ✗ | ✓ |
| `photo` | 留影 | 审核通过的照片数 | 上传时间 | ✓ | ✓ / ✓ | ✓ |
| `comment` | 便利贴 | 曾通过审核的便利贴数（删除不扣减） | 发布时间 | ✓ | ✓ / ✓ | ✓ |
| `like` | 点赞 | 给出的点赞数 | 点赞时间 | ✓ | ✓ / ✗ | ✗ |

每个统计项在注册表里声明计数方式和支持的条件。后台编辑器只显示该统计项支持的条件，后端保存时也按此校验，配不出做不到的规则（例如「立春当天浏览」）。

### 条件的含义

- **时间限定**：只统计窗口内产生的记录。日期按北京时间解释，含首尾两天。判断依据是记录本身的时间（如照片的上传时间），不是审核时间，所以窗口内上传、之后才审核通过的照片照常算数。
- **按不同天数**：窗口内有互动的天数，如「累计 5 天上传照片」。
- **按不同猫数**：涉及的不同猫数，如「为 10 只不同的猫猫拍照」。不能与指定猫猫同时使用。
- **指定猫猫**：只统计与某只猫相关的记录。浏览、关注指定猫猫时只有「有 / 没有」两种结果，数量固定为 1。

### 说明文字

`description` 留空时按规则自动生成，例如：

- 看过 30 只不同的猫猫
- 02-03 至 02-05 上传 1 张审核通过的照片
- 看过指定的猫猫

### 锁定

徽章上线或已有人获得后，整条规则（统计项、门槛、窗口、统计方式、指定猫猫）都不能再改，只能新建徽章替换。

## 四、发放

### 事件触发

互动写入成功后，立即检查该用户与此统计项相关的徽章：

| 统计项 | 触发点 |
|---|---|
| photo | `managePhoto.js` 照片审核通过（检查上传者） |
| comment | `curdOp.js` 便利贴首次通过审核（检查作者） |
| like | `curdOp.js` 点赞成功 |
| follow | `updateFollowCats.js` 关注成功 |
| view | `achievement.js` 记录浏览后的同步 |

发放出错只记日志，不影响审核、点赞等主操作，由兜底同步补发。

### 兜底同步

前端在以下时机调用 `sync`，检查全部未获得的徽章并补发：打开「我的成就」、个人资料页、「关于」页，进入猫猫详情，点赞、关注后。覆盖新上线累计徽章时的老用户、以及事件发放失败的情况。

同步时跳过还没开始的窗口，以及结束超过 30 天的窗口。结束后 30 天内仍会补发，用于覆盖审核延迟。

### 编号与并发

每条获得记录带编号 `serialNo`，表示第几位获得者，刻在徽章背面。编号由计数器在锁内分配；获得记录 `_id` 由 openid 和徽章 key 确定，同一用户同一徽章最多一条，事件触发与同步并发时不会重复发放。

### 解锁提示

新的获得记录带 `notified: false`。下次同步时，前端把这些记录弹出解锁动画（多枚可左右滑动），随后标记为已通知，同一枚只弹一次。

挂载了解锁弹窗的页面：我的成就、个人资料、关于、猫猫详情、便利贴板、榜单、我的足迹、喵友圈。

## 五、展示

### 阶梯与平铺

成就页按系列自动选择排法，不需要配置：

- **阶梯（ladder）**：系列中没有限时徽章时，按「统计项 + 统计方式 + 指定猫猫」分组，组内按门槛升序排成第 1～N 级，显示累计进度和下一级条件。
- **平铺（grid）**：系列中任一徽章带时间限定时，整个系列平铺为一张卡片，按 `sort` 排列，右上角显示「已点亮 / 总数」。每枚显示窗口日期和状态：

| 状态 | 显示 |
|---|---|
| 未开始 | 「12-03 开始」 |
| 进行中 | 图标右上角橙色角标「剩 3 天」或「今天截止」 |
| 已结束（30 天内） | 「已结束」，仍可能补发 |
| 已错过 | 「已错过」 |
| 已获得 | 获得日期 |

### 其他展示位

- **徽章详情**：正反面翻转与 3D 旋转，背面刻获得者昵称与编号，显示规则说明与当前进度。
- **个人主页展示位**：用户从已获得的徽章中选最多 3 枚展示，每个类目只能选当前最高等级。
- **成就榜**：按获得数量排名，取前 200 名。
- **新成就红点**：「关于」页「我的成就」入口显示未查看过的新徽章数。

## 六、后台管理

入口：管理页 →「用户徽章」页签（`pages/manage/badgeDef`），需内容管理（2 级）以上权限。

### 徽章状态

| 状态 | 谁能看到和获得 |
|---|---|
| 草稿 | 没有人 |
| 超管测试 | 只有 99 级超级管理员，用于在正式环境验收 |
| 上线 | 所有用户 |

- 已有人获得的上线徽章不能下线、不能删除。
- 超管测试的徽章有获得记录后只能改为上线（记录保留）或删除；删除时测试记录一并清除。
- 「全部上线」只处理草稿，逐枚校验素材与编号后切为上线；测试中的徽章需单独上线。

### 编辑徽章

- **规则**：系列、类别（统计项）、统计方式、数量、时间限定、指定猫猫，下方实时显示规则说明。上线或已有人获得后显示「已锁定」。
- **外观**：选材质、上传正面透明 PNG（≤5 MB、宽高 ≤2048）。保存后自动生成背面图和 3D 轮廓，进度显示在保存按钮上。
- **状态**：草稿 / 超管测试 / 上线；已有人获得时不可切换的选项置灰，标题旁显示获得人数。

### 材质

材质库中每种材质是一张不透明满幅纹理，用于合成背面和 3D 侧边，并决定成就名称的文字色（可自动取色或手选）。更换已被引用的材质图时，保存会重新生成所有引用它的徽章背面，按钮显示受影响的枚数。

### 立体厚度

全局设置，所有徽章 3D 侧边共用，在管理页底部调整并实时预览。

### 重新生成素材

逐枚重算全部徽章的背面图、3D 轮廓，并补齐缺失的历史编号。完成后扫描 COS，列出没有任何徽章引用的旧素材，由管理员确认后清除。

### 素材存储与清理

| 目录 | 内容 |
|---|---|
| `achievement/fronts/` | 上传的正面图 |
| `achievement/generated/` | 生成的背面图与 3D 轮廓，文件名 `<徽章 key>_<摘要>_back.png` / `_model-v1.json` |
| `achievement/materials/` | 材质图 |

- 重新生成某枚徽章后，删除它 10 分钟前的旧背面与轮廓，保留数据库当前指向的文件。
- 换正面图或删除徽章时，正面图没有其他徽章使用就删除；删除徽章还会删除它的全部生成文件。
- 批量重新生成后的孤儿扫描只列 1 天前的文件，避免误删刚上传还没保存的正面图；删除前再核对一遍。
- 材质图可能被多枚徽章引用，不自动删除。
- 清理失败只记日志，不影响保存和删除。

## 七、操作指南

### 新建累计阶梯系列

以「猫口普查」为例：同一系列下建 5 枚徽章，统计项都选「浏览猫猫」，门槛逐级递增，成就页自动排成 5 级阶梯。

1. 确定门槛（方法见第八节「门槛设定」），上线后不能再改。
2. 每枚选对应等级的材质，上传正面图，状态先存草稿。
3. 核对阶梯：同组内门槛不能重复，否则排序退化。
4. 点「全部上线」。

### 新建限时系列（以二十四节气为例）

| 项 | 建议 |
|---|---|
| 系列 | `二十四节气-2026`，带年份；次年新建系列，不复用旧徽章 |
| 类别 | 留影（也可用便利贴、点赞；浏览、关注不能限时） |
| 统计方式 / 数量 | 按次数，1 张 |
| 时间限定 | 节气日前后各放宽 1 天，共 3 天。如 2026 立春（2-4）填 `2026-02-03` 至 `2026-02-05`。日期以万年历为准 |
| 名称 / 说明 | 节气名，说明留空自动生成 |
| 排序 | `sort` 按节气顺序递增 |
| 材质 | 整个系列同一档，限时徽章不分等级 |

步骤：

1. 用第一节的 skill 一次策划 24 枚平行款正面图，保持同一画风。
2. 逐枚新建，状态选「超管测试」，保存。
3. 验收：另建一枚窗口为今天的测试徽章，用超管账号上传照片并审核通过，进「我的成就」或任一猫猫详情，应弹出解锁动画，系列平铺、角标与倒计时正确；用普通账号确认看不到测试徽章。验收用的徽章直接删除。
4. 逐枚改为上线。还没到窗口的显示「MM-DD 开始」，到期自动开放，无需再操作。

日期填错且已上线时，只能新建一枚替换；旧徽章若无人获得，可退回草稿后删除。

### 新增统计项

例如以后要统计「领养申请」：

1. 在 `achievementRules.js` 的 `METRICS` 里加一项：名称、单位、说明模板、支持的条件、计数函数。有时间记录的集合可直接用 `recordCounter`。
2. 在该互动写入成功的地方调用 `awardMetric(db, openid, '新统计项')`。
3. 需要窗口查询的，在对应集合建 `_openid + create_date` 组合索引。

后台编辑器、成就页、说明文字都从注册表读取，无需修改。

## 八、徽章设计

### 目录结构

默认目录为每个统计项一个系列，每个系列 5 级，共 25 枚累计徽章。门槛按各自项目的用户活跃分布设定（见下文「门槛设定」），不统一规定。

`key` 建议命名为 `ach_{metric}_lv{1~5}`，`sort` 按 L1→L5 递增。

### 材质

| 档位 | 材质 | key | 平均色 |
|---|---|---|---|
| L1 | 木质 | `wood` | `#B68F71` |
| L2 | 桃铜 | `bronze` | `#EDA075` |
| L3 | 浅银 | `silver` | `#CECAC9` |
| L4 | 暖浅金 | `gold` | `#FACE70` |
| L5 | 翡翠（浅青白玉 + 金缝） | `jade` | `#BEC1B5` |

材质图为 512×512 不透明满幅纹理，上传到后台材质库后存在 COS 的 `achievement/materials/`；金、银、铜三档可直接用第一节 skill 内置的金属材质。L5 明度接近浅银，靠青玉色调、金缝和正面更强的青绿描边区分。

### 细节递进

同系列逐级叠加元素，保证缩略图尺度下也能分辨等级：

| 等级 | 视觉策略 |
|---|---|
| L1 木质 | 主体 + 核心道具，木胎雕刻彩绘，无金属隔线 |
| L2 桃铜 | 同 L1 构成，改为珐琅工艺，金属隔线成立 |
| L3 浅银 | 增加 1 个配件或背景陈设 |
| L4 暖浅金 | 增加场景层或额外道具 |
| L5 翡翠 | 翠玉隔线 + 金细线、底部金色祥云浮雕、猫耳旁星芒，以及各系列专属元素 |

核心道具是系列的识别符，不随等级删减。

### 门槛设定

以「该统计项 > 0 的活跃用户」分布为口径，按百分位定档：L1 ≈ P50、L2 ≈ P75、L3 ≈ P90、L4 ≈ P95、L5 ≈ P99，同时参考全量口径，避免过易或过难，L5 必须可达。

复核时对 `user.viewedCats` / `followCats` 求去重长度，对 `photo`（`verified: true`）、`comment`（曾通过审核）、`inter`（`type: 10000`）按 `_openid` 聚合计数，再取百分位。用临时只读云函数跑一次即可。

`view` 的上限受猫的总数约束，L5 不要超过可浏览的猫数。各统计项的使用频次不同，门槛按各自分布定，不必在统计项之间对齐。

## 九、部署与运维

### 部署

后端改动都在 `unionOp` 一个云函数内。在 `functionsEMAS/unionOp` 目录打包整个目录（含 `node_modules`）为 `functionsEMAS/unionOp.zip` 上传：

```bash
cd functionsEMAS/unionOp && rm -f ../unionOp.zip && zip -qr ../unionOp.zip . -x ".DS_Store" -x "*/.DS_Store"
```

### 索引

时间窗口查询需要以下组合索引（均为非唯一、升序）：

| 集合 | 字段（按顺序） |
|---|---|
| `photo` | `_openid`、`verified`、`create_date` |
| `comment` | `_openid`、`create_date` |
| `inter` | `_openid`、`type`、`create_date` |

### COS 权限

素材生成和清理使用数据库 `app_secret` 中的 COS 密钥，需要读、写、列出和删除 `achievement/` 目录的权限。

### 批量导入

一次要建很多枚徽章时（如整套 24 节气），可以用一次性云函数 `functionsEMAS/temp/importBadges/` 代替后台逐枚录入。本地没有 COS 密钥，也不能直连数据库，所以把素材打包进函数，在云端完成上传正面图、写入徽章、生成背面与 3D。

**准备数据**：函数读取同目录的 `data.js`（已在 `.gitignore` 中排除，需自己生成），图片以 base64 内嵌，运行时不读本地文件：

```js
module.exports = {
  MATERIALS: [
    { key: 'gold', name: '暖浅金', b64: '<PNG 的 base64>' },
  ],
  BADGES: [
    { key: 'ach_solar_lichun', series: '二十四节气-2026', name: '立春', sort: 1, materialKey: 'gold',
      rule: { metric: 'photo', count: 1, window: { start: '2026-02-03', end: '2026-02-05' } },
      b64: '<正面 PNG 的 base64>' },
  ],
};
```

`MATERIALS` 只需列出要新建或更新的材质；用已有材质时留空数组，`materialKey` 填已有材质的 key。

**步骤**：

1. 把 `unionOp` 里的 `achievementBack.js`、`achievementGeometry.js`、`achievementSerial.js` 复制到函数目录，保证与生产一致。
2. 生成 `data.js`，在函数目录 `npm install` 后整体打包，在 EMAS 控制台新建云函数 `importBadges` 上传，超时设为 60 秒、内存 512 MB。
3. 依次调用：

| 参数 | 作用 |
|---|---|
| `{}` | 预览：列出将新建、将接管、因已上线或有人获得而跳过的条目，不写数据 |
| `{"apply":true,"limit":8}` | 上传材质与正面图、写入徽章（草稿），并生成最多 8 枚背面 |
| `{"apply":true,"stage":"assets","limit":25}` | 继续补背面与 3D，重复调用直到返回 `assets.hasMore` 为 false |

4. 在后台核对规则和素材，然后用后台改状态：需要验收的改为「超管测试」，否则点「全部上线」。函数自带的 `stage: activate` 会跳过后台的上线校验，不建议使用。
5. 删除云函数和本地 `data.js`。

**行为**：

- 以 `key` 为准，重跑只更新不重复新建；超时后直接重跑续作。
- 库里已有同 key 或同系列同名的徽章、同 key 或同名的材质时原地接管；已上线或已有人获得的徽章跳过，不改规则。
- 规则直接写入，不经过后台校验，`rule` 需符合第三节的约束（如浏览、关注不能带时间窗口）。

## 十、约束与已知问题

| 项 | 说明 |
|---|---|
| 规则锁定 | 上线或产生首位获得者后规则冻结，调整只能新增徽章 |
| 阶梯唯一 | 同一阶梯内不能有相同门槛 |
| 不收回 | 取消点赞、删除便利贴后，已发放的徽章不收回 |
| 时间依据 | 照片窗口按上传时间，不用拍摄时间（`shooting_date` 可由用户填写，存在补传旧照的问题） |
| 浏览、关注无时间 | 两者只记了猫 ID，不能限时；需要时再引入带时间的事件记录 |
| 组合条件 | 一枚徽章只统计一个统计项，暂不支持「任选其一」或「同时满足」 |
| 记录口径 | 成就榜与获得数量按 `achievement` 记录条数统计，不校验 key 是否仍在目录内；整体替换目录前需清理旧记录 |
| 榜单截断 | 取前 200 名后直接截断，末位同分者会被按 openid 截掉一部分 |
